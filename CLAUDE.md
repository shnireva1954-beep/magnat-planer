# Магнат — память проекта

Продукт — **одно веб-приложение**: `index.html`. Жизнь как игра-тайкун:
привычки, задачи, финансы, тело, награды. Галочки и задачи дают монеты и
опыт, опыт растит **номерной уровень** империи (каждый — здание в городе и
+50 🪙), уровни складываются в звания (🐣 Новичок → 🚀 Стартапер →
💼 Предприниматель → 🏢 Директор → 👑 Магнат), монеты тратятся на реальные
награды.

Приложение живёт в ДВУХ местах с одним кодом: здесь (сайт) и страницей-
артефактом https://claude.ai/artifact/SiEYoo6UCp7wq3u95pr7zQ. Копия кода и
проверка для рамки — в репозитории `shnireva1954-beep/-`, папка `magnat/`.
Правишь одно — переноси в другое (разница только в 4 строках шапки:
doctype, `lang`, manifest, apple-touch-icon).

Владелец делает приложение **для себя**, не на продажу.
Сайт: https://magnat-planer.ru (GitHub Pages из ветки `main`, корень репо).

**Верная ветка — всегда `main`**: сайт работает из неё. Рабочую ветку
(`claude/…`) каждая сессия Claude получает свою, постоянной нет. После
«публикуй» ветка сессии целиком лежит в `main` и больше не нужна.
29.09.2026 две такие ветки запутали владельца, какая из них верная; их
удалили. Удаляет владелец сам — корзиной на
https://github.com/shnireva1954-beep/magnat-planer/branches (удаление веток
из сессии среда не пропускает). Пять веток от июля — продажи и таблицы,
в трёх код, которого больше нигде нет: не трогать.

⚠️ Репозиторий публичный, и этот файл виден на сайте
(`magnat-planer.ru/CLAUDE.md`). Личных данных владельца сюда не писать.

## Архитектура

Статика, никакой сборки и ни одной зависимости.

- `index.html` — всё приложение: разметка, инлайн-CSS, инлайн-JS.
- `sw.js` — офлайн, стратегия «сначала сеть, кэш как запаска».
  **Не менять на cache-first** — иначе владелец застрянет на старой версии.
- `manifest.json` + `icon.png` / `icon-512.png` — установка на главный
  экран (`start_url` и `scope` — корень `./`).
- `app.html` — заглушка-редирект на `./` для ярлыков со старого адреса.
- `CNAME` — домен.

Данные: `localStorage`, ключ `magnat_app_v2`, ничего не уходит наружу.
Экспорт/импорт JSON — на экране «Обзор».

## Устройство приложения

Шесть вкладок (`TABS`), каждой соответствует функция `vXxx(root)`:

| Вкладка | Функция | Что внутри |
|---|---|---|
| 🏛 Обзор | `vHome` | уровень, серия, кольцо «Сегодня» с чипами привычек, честный «Инсайт недели», сводки, бэкап |
| ✅ Привычки | `vHabits` | календарь месяца, «Сила по неделям», «Топ привычек» |
| 🎯 Задачи | `vTasks` | список с приоритетами и сроками |
| 💰 Финансы | `vMoney` | доход/расход, пончик категорий, операции месяца |
| 💪 Тело | `vBody` | путь к цели, график веса, автоматические нормы калорий и воды |
| 🛒 Награды | `vShop` | кошелёк, награды (все правятся и удаляются) |

### Чистый лист начинается с выбора привычек (29.09.2026)

Владелец с 24.09 приложением не пользовался и выбрал это сам из четырёх
предложений. Все три входа в чистый лист — «Начать своё» в приветствии,
кнопка на демо-данных и «сбросить всё» — идут через `startFresh()` →
`pickHabits()`: окно со списком `HABITPICK`, отмечены три (🏋️ Тренировка,
📵 Лента не больше 30 минут, 💼 Шаг к работе), можно снять и добавить свою.
Пока не нажато «Начать», данные не трогаются — «Назад» после «Стереть всё»
ничего не стирает. Причина: восемь готовых привычек давали «0 из 8» каждый
день, а для серии хватает трёх отметок. `DEFHABITS` (восемь) остался для
демо-данных и для битого файла в `normalize()`.

### Цены назначает приложение, а не владелец

Владелец: «монеты не должен я сам цену назначать». Ни одного поля с ценой
в интерфейсе нет:

- **Привычки.** Ровная ставка `COIN = 20` монет за любую отметку
  (`baseCoins` = число отметок × COIN). Разницу делает не ценник, а серия:
  множитель до ×2. У привычки больше нет поля `coin` — при добавлении
  спрашивают только название.
- **Награды.** Живут одним списком `S.rewards` (встроенные приезжают из
  `DEFREWARDS` и правятся/удаляются наравне со своими), счётчики покупок —
  в `S.boughtCnt`. **С 24.09.2026 цена — в ПРИВЫЧКАХ** (`r.n`, `SIZES`:
  5 / 15 / 40 / 150), в монетах = `n × COIN` (`rwCost`). На карточке
  написано «= 5 привычек». Владелец: «откуда цена читмила? отталкивает» —
  прежняя цена «дни × средний заработок за 2 недели» выглядела случайным
  числом. Старые `days` 1/3/7/30 переезжают в 5/15/40/150 (`OLDDAYS`).
- **Встроенные награды — привычные удовольствия** (владелец: «посидеть в
  TikTok», «отдых — лишнее»): TikTok, игры, читмил, кино, вещь, поездка.
  «🛌 Выходной» убран, у живых данных тоже — разово, флаг `S.rv = 2`.
- **Откуда монеты:** привычка +20 (× серия до ×2), выполненная задача +20
  (`TASKCOIN`), каждый новый уровень +50 (`LVLBONUS`, только в кошелёк,
  не в опыт). Удалённая выполненная задача монеты не отнимает — они
  уходят в `S.taskBank`. Снятая галочка задачи — отнимает (иначе ферма).
- Миграция старого формата (`bought` по индексам, `myRewards`, `boughtMy`)
  живёт в `normalize()` — не удалять, у владельца данные того формата.

### Уровни империи (24.09.2026)

Владелец: «в империю добавить уровни… показывалось, на каком ты уровне, а
не просто цыплёнок». Было пять ступеней (0/300/1500/5000/15000 ⭐).
Стало: опыт до уровня L = `20·k·(2k+3)`, k = L−1 (2-й — 100 ⭐, 5-й — 880,
10-й — 3 780, 20-й — 15 580), `levelOf()` / `xpForLevel()`. Звания —
`RANKS` по номеру уровня (1 / 3 / 6 / 11 / 19); пороги подобраны так, что
при переходе **ни у кого звание не упало** (проверено перебором 0–200 000).
Город (`skyline()`) — одно здание за уровень плюс стройка следующего;
та же рисовалка и в карточке «Поделиться». `S.lastLv` — самый высокий
отпразднованный уровень (не опускается: снял/поставил галочку — второго
праздника нет). Старое `lastLvl` не переносится; у кого его нет, но
уровень > 1 — один раз окно «В империи теперь уровни».

### Эмодзи в названии

Иконка — это эмодзи в начале названия, и он **снимается**: стёр — значит
иконки нет. Раньше `ico` подставлялся обратно из старого значения, и
смайлик было не убрать. Разбор — `parseIco()` (понимает составные вроде
🏋️‍♂️), вывод — только через `withIco()`, никогда не `${h.ico} ${h.name}`.

### Нормы калорий и воды (экран «Тело»)

Владелец: «надо чтобы считалась сама, а то какой смысл». Руками ничего не
вбивается, всё выводится из данных:

- `bmrValue()` — **Миффлин — Сан Жеор**: `10×вес + 6,25×рост − 5×возраст`
  плюс `+5` мужчинам и `−161` женщинам. Вес берётся последний из журнала,
  возраст — из года рождения, поэтому обновляется сам.
- `actFactor()` — коэффициент активности. По умолчанию `auto`: считает
  ДНИ с тренировкой за 28 дней по собственным отметкам привычек,
  переводит в тренировки в неделю → 1.2 / 1.375 / 1.55 / 1.725 / 1.9.
  Можно выбрать уровень вручную. **Какая привычка — тренировка:**
  `isWorkout(h)` — флаг `h.sport`, если владелец его ставил (✏️ у
  привычки → «💪 Это тренировка»), иначе догадка `RE_SPORT` по названию.
  «Зал» и «йога» — только отдельным словом: до 24.09 «День без
  залипания» считался тренировкой и завышал норму. Какие привычки
  считаются — написано в профиле (`actLine`), владелец спрашивал «каким
  тренировкам?». Без lookbehind: его нет в старом Safari.
- `norms()` — TDEE = обмен × активность, дальше поправка **по расстоянию
  до цели**: снижение `cutPct` = 8% + 1,5% за кг, в пределах 10–25%;
  набор `bulkPct` = 4% + 1% за кг, в пределах 5–15%. Было ровно −15% /
  +10%, и владелец видел: «меняю цель — норма не меняется». Под нормой —
  темп (≈ кг в неделю, 7 700 ккал = 1 кг) и срок до цели, после смены цели
  тост с новой нормой. **Ниже основного обмена не опускаемся** (`floored`).
- Вода — 30 мл на кг веса, плюс 0,5 л в день, когда тренировка отмечена.
- Профиль (пол, рост, год рождения, активность) живёт в `S.body`,
  редактируется `editProfile()` с проверкой диапазонов.
- Ручное значение остаётся возможным: `calManual` / `waterManual`. Пустое
  поле в форме возвращает автоматический расчёт.

Формула названа прямо в интерфейсе и помечена как оценка, а не назначение
врача — цифры должны быть объяснимы, это то же правило честности.

### Движок серий и опыта

- `h.since` — дата, с которой привычка считается. `""` значит «была всегда».
  Новая привычка получает `since = TODAY`, поэтому **не роняет задним
  числом все прошлые проценты**. Знаменатель везде — `poolOn(d)`, а не
  `S.habits.length`. Отметка клетки раньше `since` двигает `since` назад.
- `dayGoal(d)` = `min(DAYOK, poolOn(d))`, но не меньше 1. С одной-двумя
  привычками серия раньше была **невозможна в принципе** (порог 3 жёстко).
- `stats()` — один линейный проход по датам: опыт, рекорд серии и карта
  «серия на дату». Кэш сбрасывается в `save()` и в начале `draw()`.
  Раньше каждый день истории обходил всю историю: с двумя годами отметок
  перерисовка занимала 540 мс, стало 7–18 мс. **Не возвращать обход в
  цикле** — `streakEndingOn` теперь просто читает карту.

### Мелочи, которые чинились по жалобам пальцев

- `.ovl` прокручивается, `.modal` центрируется через `margin:auto` — на
  низком экране с открытой клавиатурой кнопка «Готово» была недостижима.
- Цели для пальца `.del` / `.ted` / `.si .rm` — 40×40. Было 21×22, и
  одно касание мимо стирало данные.
- Удаление операции в «Финансах» спрашивает подтверждение (деньги жалко),
  задачи удаляются сразу — там цена ошибки мала.
- **`header` имеет `padding-top:env(safe-area-inset-top)`.** С домашнего
  экрана iPhone (`black-translucent` + `viewport-fit=cover`) статус-бар
  лежит поверх страницы: время налезало на «Магнат», LTE — на кошелёк.
  Не убирать.
- Полоса вкладок гасит край только с той стороны, где вкладки продолжаются
  (`.tabs.fl` / `.tabs.fr`, обновляет `tabFades()`). Постоянная маска
  обрезала последнюю вкладку даже в конце прокрутки. Активная вкладка
  доводится до центра при каждой перерисовке.
- Один замер веса рисует точку и подпись, а не залитый во весь блок
  прямоугольник (`weightChart` при `log.length<2`).
- Покупка награды и удаление операции спрашивают подтверждение; вес, цель
  и ручные нормы проверяются **внутри формы** (`askModal(...,{check})`,
  строка `.ferr`) — раньше опечатка закрывала форму и всё вводилось заново.
- `grid-template-columns` только через `minmax(min(250px,100%),1fr)`:
  голый `minmax(250px,…)` шире узкого контейнера и даёт скролл.
- `save()` при переполнении хранилища показывает тост, а не молчит.
- `.toast` имеет `z-index:90`: раньше тонул за затемнением формы, и
  сообщение «Впиши сумму больше нуля» не было видно.
- «Инсайт недели» молчит, пока данных мало: неделя к неделе требует по
  4 прожитых дня и базу от 15%, слабый день недели — хотя бы 3 замера и
  только с первой отметки. Иначе выдавал «+600%» и обвинял дни, когда
  приложения ещё не было.

Ключевые общие места: `normalize()` чинит любые данные на входе;
`render()` → `draw()` в try/catch, при падении `rescue()` показывает экран
с выгрузкой данных вместо белого экрана; `num()` — единственный
правильный способ прочитать число из поля; `uid()` — id без коллизий;
`TODAY`/`CURMONTH` живые, обновляются `refreshToday()`.

## Правила, которые нельзя нарушать

- **Честность.** Никаких выдуманных цифр и статистики вида «лучше 84%
  пользователей». «Инсайт недели» считается только из реальных локальных
  данных, иначе не показывается вовсе.
- **Одна яркая эмоция = одно достижение.** Празднуется только новый
  уровень. Конфетти на каждое действие — нельзя. Монета летит в кошелёк
  при отметке привычки или выполненной задаче — это максимум.
- **Окно Claude — не браузер.** Там (страница в рамке, `FRAMED`) не
  работают `confirm()` (сразу «нет»), скачивание ссылкой и «Поделиться».
  Поэтому подтверждение только через `askConfirm()`: на сайте — системное
  окно, в рамке — своё. Копия данных в рамке — текстом, картинка — в окне.
- `prefers-reduced-motion` уважается везде (`RM` в коде).
- Тексты — с настоящими тире «—», не дефисами.
- **Числовые поля только `type="text"` + `inputmode`.** `type="number"`
  отбрасывает запятую («82,4» → пустота), из-за этого вес молча не
  сохранялся. Не возвращать.
- Flex-элементы с `flex:1` и длинным текстом обязаны иметь `min-width:0`,
  иначе на 320px появляется горизонтальный скролл всей страницы.

## Проверка изменений

**Тесты лежат в репозитории, в папке `tests/`.** После любой правки
`index.html`:

```bash
npm i playwright-core      # один раз
node tests/run.js
```

Прогон занимает несколько минут и заканчивается либо «ВСЁ ЧИСТО», либо
списком проблем. Что внутри — подробно в `tests/README.md`. Коротко:
`01-scenarios` (онбординг, все экраны, реальные действия, битые данные,
полночь, ширины, нормы, монеты, награды, миграция), `02-edge` (края и
пустые состояния), `03-stress` (альбомная, зум, нагрузка), `04-final`
(обновление версии, копия данных настоящим файлом, часовые пояса, обход
всех кнопок, две вкладки, триста перерисовок).

`node_modules` и `package*.json` **не коммитить** — они в `.gitignore`.

Чего тесты не заменяют: настоящий Safari на iPhone, установку на главный
экран и поведение при плохой сети. После заметных правок стоит один раз
пройтись по экранам на самом телефоне.

## Публикация

Только по прямой команде владельца «публикуй»: fast-forward `main` до

сеть первым делом).
